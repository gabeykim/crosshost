# Figure audit — Gate 11, Task 4.2

**Method.** For every `.png` file in `out/figures/` (31 total), searched `scripts/*.py` for the exact basename to find its producing script — the same method `scripts/audit_provenance.py` uses, with the same disclosed limitation: a textual-mention match is not proof a script *currently* regenerates the exact file (a script can merely reference a stale file's name in a comment or a triage list). Every figure was checked by hand against that limitation before being included here, per the audit script's own docstring instruction ("investigate each one by hand before trusting or retracting it").

**Result: 28 of 31 figures have a real, current producing script and are included in this package (9 main text, 19 supplementary). 3 are excluded, for cause, below.**

## Excluded figures, and why

**`gate5_5_performance_vs_ceiling.png`** — visualizes the "percent of cross-host measurement-correlation ceiling" metric, which was **retired outright in Gate 7** (Limitations item 7 / `out/KNOWN_ISSUES.md` item 7): the sequence-only model genuinely exceeds the correctly-computed ceiling for *B. subtilis* (102–111%), a real measurement-noise artifact, not a metric worth shipping. `scripts/77_regen_remaining_figures.py`'s own docstring states this file is "deliberately NOT regenerated" and is superseded by `gate8_ceiling_anomaly_resolution.png` (included here as Figure S9, historical/explanatory only). **Excluding this file is not a new finding — it was already known and disclosed — but it belongs in this package's audit trail rather than silently omitted.**

**`gate6_pct_of_ceiling_corrected.png`** — also visualizes the retired percent-of-ceiling metric, this one from the intermediate Gate 6→7 correction (`scripts/65_gate6_figures.py`'s own title: *"Gate 6 (corrected): percent-of-ceiling by system — NOT the previously-reported..."*). Even though this version corrects Gate 6's own error, the underlying metric was subsequently retired for the separate, deeper reason above and "does not appear anywhere in this paper's baseline tables" (Limitations item 7). Including it in a submission-ready figure set would resurrect a metric the manuscript text explicitly says is absent. **Excluded for consistency with the manuscript's own stated policy, not because the figure is inaccurate.**

**`gate5_5_crosshost_measurement_correlation.png`** — a genuinely new finding from this audit, not previously disclosed. `scripts/67_crosshost_correlation_figure.py`'s own docstring states: *"the original `out/figures/gate5_5_crosshost_measurement_correlation.png` had no producing script — flagged by `scripts/audit_provenance.py`"* — that script was written specifically to regenerate the same underlying numbers (`out/results/gate5_5_crosshost_measurement_correlation.json`, independently re-verified reproducible bit-for-bit) under a **new filename**, `gate7_crosshost_measurement_correlation.png`. The original orphaned file was never deleted from `out/figures/`, so it still exists on disk with no live producing script pointing at *that exact filename* — `audit_provenance.py`'s textual-match check is satisfied only because `scripts/67`'s docstring mentions the old filename while explaining why it replaced it, not because any script regenerates it. **This package uses the regenerated file (`gate7_crosshost_measurement_correlation.png`, included as Figure S8) and excludes the stale original.**

## A note on what this audit surfaced about `audit_provenance.py` itself

`scripts/audit_provenance.py`'s own docstring already discloses its method is a heuristic ("plain textual match... will have false positives... a script that only ever READS a file"). This figure-by-figure check confirms that disclosure is accurate and load-bearing: the "0 orphans" result reported in every gate's audit output means *some* script mentions every filename, not that every filename is *currently regenerated* by a live plotting call. The distinction mattered for one of the three exclusions above (`gate5_5_crosshost_measurement_correlation.png`) and is worth carrying forward — a future gate relying on "0 orphans" to mean "every figure is live" would be trusting the check past what it actually verifies. **Recommendation, not acted on this gate (no code changes were in scope):** `out/figures/gate5_5_performance_vs_ceiling.png` and `out/figures/gate5_5_crosshost_measurement_correlation.png` could be deleted from `out/figures/` as cleanup, since neither is regenerable from a current script and both are superseded; left in place here since deleting files was not requested and the manifest/audit trail already documents their status.

## Resolution

All included figures are 150 DPI PNGs (`out/figures/*.png`, generated via `matplotlib` `dpi=150` throughout, e.g. `scripts/73_attenuation_figures.py` line `fig.savefig(..., dpi=150)`). **Stated plainly: 150 DPI is screen/preprint-appropriate, not the ≥300 DPI some print journals require for line art.** No figure was regenerated at higher resolution for this package — doing so would require re-running each producing script with a changed `dpi` argument, which is mechanical but was not done this gate to avoid touching result-generating code paths outside this gate's stated scope (assembly, not new analysis). If a venue requires 300 DPI, every figure's producing script accepts this as a one-line change (`fig.savefig(path, dpi=300)`) with no recomputation of underlying numbers.
