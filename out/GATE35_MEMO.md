## TASK 2 — v1.0.1 preparation

### Step 1 — the root LICENSE will NOT be detected. This is the blocker.

```
gh api repos/gabeykim/crosshost        -> license: NOASSERTION, name: "Other"
gh api repos/gabeykim/crosshost/license -> detected from: LICENSE, spdx: NOASSERTION
```

GitHub finds the file and declines to identify it. The cause is the scope addendum I added in Gate 33: GitHub's `licensee` matches a licence file against known templates by similarity, with a high threshold, and the addendum is ~29% of the file. The MIT body itself is byte-identical to the canonical template — I verified that again here — but the file as a whole is not.

**I predicted the opposite in Gate 33** ("the MIT body is 71% of the file, so GitHub's detector should classify it as MIT rather than Other"). That was a guess stated as an expectation, and it was wrong. The correct check was one `gh api` call, which I did not make until it mattered.

**Why this blocks the release:** Zenodo takes the licence from the repository's *detected* licence. With `NOASSERTION` it will fall back to its default — CC-BY-4.0 — which is precisely the mismatch v1.0.1 exists to correct. Releasing now reproduces the bug.

**Proposed fix, for your approval — not applied:** move the scope addendum out of `LICENSE` into a root `NOTICE.md`, leaving `LICENSE` as the canonical MIT text alone, and add one line at the end of `NOTICE.md`'s intro pointing back. `LICENSE` then matches the template exactly and detects as MIT; the scope statement survives verbatim, one file away, referenced from the README and from `package/LICENSE`. This reverses the *form* of Gate 33's decision, not its substance, so it is yours to approve.

Alternative if you would rather not touch `LICENSE`: publish the release and then edit the licence field manually in the Zenodo record. That works but leaves GitHub showing "Other" to anyone browsing the repository.
